# 根因证据链及尚未解决的问题

**结论：ROOT_CAUSE_IDENTIFIED_REPAIR_FAILED。** 本文将观测、干预和推断分开；详细数值及图表见report_zh.md。

## 1. 最早分歧不是P−1本身

原F/B与F/C在L1的共同文本行中，输入、Norm、Q/K/V及旋转后Q/K、共同有效分数和概率均相同。第一处非零差异是AV输出，4个文本元素、最大差6.103515625e−05。前六层P−1更新为零，故其自身直到L7才出现不同。只追踪P−1会误判起点。

同输入Shadow将122行与121行Attention比较，重现形状差异；附加一个因果上永不生效的零K/V列后，AV恢复严格一致。这将早期差异具体定位于形状相关算子数值行为，超出了“可能是BF16”的猜测。

## 2. 退出有独立的数值来源

W22/P拥有相同功能权限，不包含早期Attention跳算的不同。L22共同文本输入及Norm严格相同，k_proj在122/26行计算下开始不同。B/C得到同类结果。相同输入BF16投影也复现K/V及gate/up差异；FP32诊断差异远小于BF16。Q/o/down并非所有算子都会随行数改变输出。

没有Profiler证据确定具体CUDA核函数、算法编号或归约树。只能确认在本硬件/依赖/输入的BF16计算形状改变后产生可复现差异，不能把“形状敏感”进一步写成未经测量的特定cuBLAS缺陷。较接近FP32也不等于更接近冻结功能性参考；验收以F为准。

## 3. 已排查的语义路径

共同位置的Mask许可、原始位置、mRoPE cos/sin及三次DeepStack注入一致。逐层Cache快照确认Prefill储存正确K/V Gather、Decode只追加且旧前缀未改变，L1–L6跳算没有KV。36层MLP/Norm/Residual保留，Context正常/异常退出恢复Hook。没有发现可通过修Mask或位置索引消除的语义错误。

CompactKV的合法Key与参考路径一致，但物理维度不同，仍可改变BF16乘法/求和结果；不能用逻辑许可相同保证数值逐位相同。当前残余Decode差异未获得与Prefill一样细的逐算子定位，不能声称其完整机制已证明。

## 4. 唯一完整修复候选及反证

候选仅在早期Prefill给121个真实KV增加一个禁止读取的临时零Key。没有投影P−1，没有增加持久KV，没有恢复真实Decode Attention，没有取消L22退出。

F/B首步完整Logits由mean0.0977548063变为0，说明早期Prefill差异确可通过受控形状变化消除。但F/B真实Decode mean仍为0.0508070588；F/C修复后两步mean0.0523297191与0.0677602813，均超过0.02。原输入没有通过，故没有运行其他长度输入。不能用Top1和no+EOS相同宣告修复完成。

四种预先冻结的BF16线性算子表达形式没有同时恢复全部被测K/V/gate/up投影，因此未追加完整候选。未尝试恢复近密集Hidden行或将FP32用作正式路径。

## 5. 分析侧标签修正

原探针以长度推断Key位置，在121+1零列时把最后列标记为P−1。该列实际为常零Dummy，概率严格0；CPU对齐侧改标为−1，避免将死Key原始未Mask分数误认为有效连接分歧。修正没有写回原始张量，没有更改模型Mask或位置。完整侧车记录位于repair_dummy_key_alignment.json。

## 6. 能得出的工程结论

原始失败不应通过放宽平均误差阈值处理。早期Prefill的局部修复可行，但完整物理候选仍未满足固定参考的数值门槛，晚期投影与Decode紧凑Key归约是后续独立数值工程的目标，而不是本轮已完成的成果。当前不具备正式质量和性能评测前置条件。本结论只针对所测固定输入和候选，不证明物理C3在BF16下普遍不可能实现。
